# Bottleneck split for the 200 ppm clock-drift weakness

Generated by `crates/cf-aec/tests/drift_split.rs` from the same deterministic, `std`-only scene generator as `ROBUSTNESS.md`. Re-run with:

```text
cargo test -p cf-aec --test drift_split -- --nocapture
```

## Verdict

The drift loss is **filter adaptation lag against a moving optimum** (factor 3), not delay-estimator churn (factor 2), and not the initial alignment.

* Mean post-window echo ERLE is **18.9 dB** with a static delay (A) and **3.4 dB** with 200 ppm drift (B): a **15.5 dB** loss.
* In B, **9 of 27** drift runs are below the 3 dB collapse line; with the exact rate correction **0** are (worst 4.2 dB).
* Pinning the delay at the true initial value (C) gives **4.1 dB**. That is **+0.6 dB** relative to B and leaves **14.9 dB (96 %)** of the loss in place. The filter cannot absorb the ramp even when the estimator is not allowed to move.
* The estimator changed the applied delay **0** times after the initial lock across 27 drift runs. There is no re-lock churn to gate or hang over.
* Raising the NLMS step size from 0.50 to 1.00 gains **+1.7 dB** with estimation on and **+1.6 dB** with the delay pinned: real, but far too small to close a 15.5 dB gap.
* An exact rate-corrected reference (D-rate) gives **18.9 dB**, matching the static bound of 18.9 dB on average and within 0.5 dB on every scene. Removing the motion from the reference recovers almost all of the loss.
* A residual rate error of 10 ppm still gives **17.2 dB** mean, 25 ppm gives **13.9 dB**, and 50 ppm gives **10.5 dB**. The rate estimate does not need to be exact to remove the collapse.

### The implemented correction

E is the clock-rate correction that this experiment led to, now in the default configuration: the reference-to-microphone ratio is estimated from the correlation profiles the delay estimator already computes, and the aligned reference is resampled by a four-point cubic before it enters the adaptive filter. It reaches **17.2 dB** mean against the static bound of 18.9 dB and the perfect-rate ceiling of 18.9 dB, i.e. **1.8 dB** below the ceiling and **13.8 dB** above the uncorrected behaviour. It engages on **27 of 27** drift runs.

* Collapses below 3 dB: **0 of 27** (worst 4.3 dB), against 9 before the correction and 0 for the exact one.
* Convergence: the correction engages at frame 197 [160, 368] on average, and its applied rate is within **3.9 ppm** of the true 200 ppm on average over the post window (worst 32.5 ppm). The estimator's fit window needs six measurements after the first lock, and each measurement is one 256 ms correlation profile; that is the acquisition cost, not a filter-reset cost.
* The remaining 1.8 dB gap to D-rate is convergence lag, not rate error: the filter needs a few hundred frames of *static* path to converge, and before the correction engages (frames 0 to about 200) the path has already slid by roughly 10 samples. The per-scene worst case is 4.1 dB below the matched static scene.

## Conclusion

**Dominant factor: filter adaptation lag (factor 3).** With the bulk delay pinned at the true initial value the estimator is out of the loop, yet **14.9 of the 15.5 dB** is still lost: the fixed alignment falls about 33 samples behind the path over the file, and the adaptive filter cannot follow that moving optimum. Delay-estimator churn is absent (0 applied-delay changes in 27 runs), so gate or hangover tuning has nothing to fix on these scenes. The accumulating alignment error is the physical ramp behind the lag, but a better initial lock does not help (+0.6 dB for pinning at truth); only continuous tracking removes it. Filter tuning is also not the lever: step size 1.00 buys +1.7 dB.

**Fix: estimate and remove the clock rate.** The exact correction recovers 18.9 dB against a static bound of 18.9 dB; a rate estimate within 10 ppm still gives 17.2 dB and within 25 ppm gives 13.9 dB. The implemented estimator (E) reaches 17.2 dB. The delay re-lock gate/hangover is never exercised here, and step size, regularisation and tail length buy at most +1.7 dB; D-rate keeps the same 2048 taps and recovers the bound, so the tail is not the drift bottleneck.

The cheaper partial variant - incremental delay adjustments without a filter reset - is not competitive: D-repin, which re-pins through the public interface and pays the reset, reaches only 5.3 dB.

## Conditions

Every row starts from the same generated room, noise and double-talk scene; only the echo path's bulk-delay behaviour changes. A is the matched scene with a static delay. The scene list is every `drift200ppm` row of the room matrix: the six clean room families plus the three combined drift + noise + double-talk stress scenes.

* **A** static delay, estimation on: the upper bound for this room/noise/DT.
* **B** 200 ppm drift, estimation on, clock-rate correction off: the behaviour recorded before the correction existed.
* **C** 200 ppm drift, estimation off, delay pinned to 480 samples (the true initial bulk delay) with `set_delay_override`.
* **D-repin** 200 ppm drift, estimation off, override re-pinned every 64 frames to the instantaneous true bulk delay. Each change resets the adaptive filter in the current API, so this is periodic re-alignment through the public interface, not an ideal tracker.
* **D-rate** 200 ppm drift, estimation on, far-end reference resampled by the exact drift ratio so the effective echo path is static. This is the perfect-rate-tracking ceiling.
* **E** 200 ppm drift, default configuration: the implemented clock-rate correction (`Aec::clock_rate_ppm` reports the applied rate, `Aec::clock_rate_corrected` the switch).

Cells are `mean pre -> mean post [min post, max post]` over the three seeds `00C0FFEE`, `5EED1234`, `A5A55A5A`, in dB. Post is frames 480-620 (7.68-9.92 s); pre is frames 150-240 (2.40-3.84 s). Echo ERLE removes the known noise from the residual, exactly as in `ROBUSTNESS.md`. `re-locks` counts applied-delay changes after the initial lock, summed `[worst seed]`; `norm` is filter norm at the end of the post window / the run peak.

## Secondary observation: double-talk freeze

The post-window freeze columns show the share of frames on which the double-talk detector stopped adaptation, including E. Before the stationary-floor gate, the target office+pink+15 dB+double-talk scene (row 51) froze adaptation on 48 % of post-window frames; 40 % of those frozen frames were far-end pauses and 67 % had a microphone power within 2x of the true background noise power, while only 20 % of the freezes during real double talk were that close to the floor. That is a false detection, not double talk, and it kept the filter from re-converging after the path had drifted. With the gate, E freezes on 9 % of post-window frames and posts **15.8 dB** instead of 12.5 dB; the matched static control posts **19.9 dB** with 10 % freeze. The remaining freeze costs about **0.3 dB** on E (measured by disabling the freeze after the double-talk segment); it is no longer the main term. What is left of the gap to A is drift acquisition and post-double-talk convergence, not the detector.

## Scope and changes

The rate correction (E) is `cf-aec` algorithm code: `src/rate.rs` (the estimator) and the fractional read in `src/delay.rs`. Everything else here is test-only. Two additive test-helper changes were needed earlier: `window_echo_erle` in `tests/room/mod.rs` is now `pub` so both test binaries use the identical ERLE definition, and the `matrix.rs` unit-test import uses `crate::room::{...}` so the module can be included from a second integration-test binary. The re-lock count is derived from the public per-frame `Aec::delay_samples()` trace and the correction's convergence and rate from `Aec::clock_rate_corrected()` / `Aec::clock_rate_ppm()`; no estimator state is exposed.
